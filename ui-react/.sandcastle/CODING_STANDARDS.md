# Coding Standards — ui-react

The reviewer agent loads this during code review. These are the conventions for
the `ui-react/` React app (see `ui-react/CLAUDE.md` for the full context).

## Stack constraints

- React 18 + TypeScript in **strict** mode (`noUncheckedIndexedAccess` is on —
  index/array access is `T | undefined`, handle it).
- Do **not** introduce legacy `ui/` (LitElement) patterns: no Redux, no Webpack,
  no LitElement decorators, no `@lit/reactive-element`.
- State: React Context + Apollo cache only. No Redux.

## Style

- Prefer **named exports** over default exports.
- Always import via the `@/` path alias (maps to `src/`). Never use deep relative
  paths like `../../..`.
- `camelCase` for variables/functions, `PascalCase` for components/types.
- Use the `cn()` helper (`@/lib/utils`) to compose Tailwind class names.
- Avoid nested ternaries; prefer early returns or `if/else`.
- No unused locals or parameters (tsconfig enforces `noUnusedLocals` /
  `noUnusedParameters`).

## UI components

- Follow the shadcn/ui pattern: primitives in `src/components/ui/` (thin Radix +
  CVA wrappers); feature components compose them under `src/components/<feature>/`.
- Do not hand-edit `src/graphql/generated/graphql.ts` — it is generated by
  `npm run codegen`.

## Forms

- React Hook Form + Zod. Define the Zod schema (in `src/schemas/`), derive types
  with `z.infer<>`, and wire it through `zodResolver()`.

## Testing

- Every new component needs a test. Co-locate at
  `src/components/<name>/__tests__/<Name>.test.tsx`; cross-cutting tests go in
  `src/__tests__/`.
- Vitest + Testing Library + MSW 2. Use `renderWithProviders()` from
  `src/test/utils/render.tsx` rather than bare `render`.
- Test observable behavior, not implementation details.

## Architecture

- Keep modules focused on a single responsibility; prefer composition.
- No speculative abstractions or configurability that the issue did not ask for.
- Surgical changes only — every changed line should trace to the issue.

## Gotchas (flag these in review)

- **`@tanstack/react-table` infinite loops.** When `data` changes on every
  render/keystroke (e.g. a custom search feeding `data`), `autoResetPageIndex`
  (default `true`) can cause an infinite synchronous re-render loop that **hangs
  the test suite** (vitest's `testTimeout` can't interrupt a blocked event loop).
  Require `autoResetPageIndex: false` (or an explicit page reset) in that setup.
  Also keep `columns` and `data` referentially stable (`useMemo`).

## Before committing

Run from inside `ui-react/`: `npm run typecheck && npm run test`. Both must pass.
