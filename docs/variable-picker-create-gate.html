When the variable isn't in the catalog, open a door — not a dead end.

The modal needs a controlled way into "create a new standard variable." This is just the gate — where it lives and how it behaves — not the creation form behind it. It's deliberately available but not eager: quiet while browsing, primary only at a true dead-end, and it always shows near-misses first so we don't mint another duplicate of the 423 concepts already there.

How the gate behaves

  • Two placements. A quiet footer gate that's always present while browsing, and a primary gate that only takes over at a real dead-end (search with no match).
  • Find-before-create. The dead-end shows "Did you mean…" near-misses first. This is the guardrail against the 176 duplicate rows we already have in the data.
  • Carries context. The gate hands the typed query (and the phenomenon, if one's selected) to the form so it can pre-fill — the gate just passes it; it doesn't collect it.
  • Permission-aware. Creating writes to a shared catalog, so the gate is only live for an authenticated user (anonymous role is SELECT-only).

Where it plugs in

The combobox already stubs this: StandardVariableCombobox takes an optional onRequestNew prop. The gate fires it; the parent (the modal) swaps the picker for the create form.

On submit, the form inserts into modelcatalog_standard_variable (id, label, description, same_as) — the new id flows straight back into the same standardVariable field. No schema change.
