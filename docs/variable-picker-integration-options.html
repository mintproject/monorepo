MINT · Register Model · Option C integration

One Input row. Three ways to open the guided variable + unit picker.

Option C merges the two independent Standard Variable and Unit fields into a single guided flow (phenomenon → property → unit). The form schema and mutation stay the same — only how the picker opens changes. Here's that exact moment, in the real Input-row context, rendered three ways. Click the field to open each.

Plugs into InputRow.tsx Writes standardVariable.id + unit.id Schema unchanged

Modal dialog

recommended

The merged field is a compact trigger. Clicking it opens a centered modal with the full guided flow — maximum room for the two columns and the unit step, total focus, and it never clips inside a scrolling multi-row form.

Register Model → Inputs → Input 1 — click the variable field

What it's like

  • Most space. The phenomenon→property columns and unit cards all breathe; no truncation even with 8 domains.
  • Focus. Dims the form so the user does one thing: resolve this variable. Good for a deliberate, infrequent action.
  • No clipping. Works the same whether it's Input 1 or Input 12, and survives the form scrolling.
  • shadcn Dialog — already in the kit; nothing new to pull in.
For

Best ergonomics for the hardest field on the form. Scales to any number of rows.

Cost

An overlay is a heavier gesture; pulls the eye away from the row's other fields.

Wide popover

in-context

Same trigger, but the flow drops down anchored to the field — wider than the trigger, floating over the form. Lightest gesture, keeps the row visible, mirrors how the current combobox already behaves.

Register Model → Inputs → Input 1 — click the variable field

What it's like

  • In context. The row stays put; the picker feels like an extension of the field, not a detour.
  • Familiar. Same mental model as today's StandardVariableCombobox popover — least retraining.
  • Lightest. No backdrop, fast open/close for users adding many inputs quickly.
  • shadcn Popover — also already in the kit.
For

Speed and context for power users adding row after row.

Cost

Can clip near the viewport edge / bottom of the page; tighter vertical room for the unit list.

Inline expand

no overlay

No floating layer at all — the row itself expands and the guided flow appears in place, pushing the rest of the row down. Everything stays on one surface.

Register Model → Inputs → Input 1 — click the variable field

What it's like

  • One surface. Nothing floats; the whole interaction is part of the document flow.
  • Always visible. The user keeps the row's Label/Format in view while choosing.
  • Tradeoff: it shoves. With several inputs, expanding one pushes the others far down — the form gets tall and jumpy.
  • Tightest space. Constrained to the row width; the two columns get cramped on narrow screens.
For

Simplicity; avoids overlay/z-index entirely.

Cost

Layout jump with many rows; least room for the flow. Weakest of the three for a dense form.

→

My recommendation: modal dialog

Choosing a variable + unit is the most cognitively loaded field on this form and is done a handful of times, not hundreds. The modal gives the phenomenon→property→unit flow the room it needs and behaves identically no matter how many rows exist or how far the form has scrolled — the two failure modes of popover and inline. If quick repeat-entry turns out to matter more than focus, the same picker component drops into a Popover with a one-line change, since the body is container-agnostic.
