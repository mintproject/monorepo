## Summary

Retrofit the MODFLOW-2000 debug notebook to model-catalog-api v2.1.0. Switch BASE_URL to local server, migrate every relationship-array literal from bare-string ids to object form `[{"id": ...}]`, replace pre-fix workaround narrative with happy-path descriptions, add bootstrap for missing seed data, and add four new step pairs that exercise the bug-087 + bug-089 fixes (recursive nested POST, replace-subtree PUT, mixed inline-new + link-only, acceptance-gate summary).

## Problem

The notebook encodes assumptions that the live v2.1.0 server now violates:

1. Relationship arrays use bare-string ids (`hasInput: ["id"]`). v2.1.0 returns `400 STRING_ID_DEPRECATED`.
2. Header + Step 4/5/8/9 markdown frame the API as broken (cascade-null bug, mirror trick required, SVO query expected empty). All three are fixed in v2.1.0.
3. Step 1 asserts a synthetic test VP exists, but the local server is fresh and does not have it.
4. Notebook does not exercise the bug-089 superpowers (recursive nested POST, replace-subtree PUT, mixed link/inline at depth).

## Requirements

Locked decisions:

1. **Target = local server** `http://api.models.mint.local`. Production server stays on whatever URL it has — out of scope.
2. **MODFLOW framing preserved.** Notebook stays a MODFLOW-2000 demo (no rebrand to Cycles).
3. **Self-bootstrap seed VP.** Step 1 GETs `EXISTING_VP`; on 404 it POSTs the VP itself, then re-GETs.
4. **Object-form id arrays everywhere.** No bare-string fallback. v2.1.0 rejects on purpose.
5. **TLS untouched** (`VERIFY_SSL = True`). Auth flow untouched (Tapis password grant + env-var fallback).
6. **Per-run uuid-suffix ids preserved.**
7. **Status-code assertions:** `assert r.status_code in (200, 201)` for POST. `200` for PUT/GET.
8. **Cell discipline:** one markdown + one code cell per step, never folded. Existing `cell_id`s preserved on edits. New cells appended at end with new ids.
9. **Print summaries preserved** as the demo's user-facing output.

## Out of scope

- Rebranding the notebook to a non-MODFLOW model.
- Changing Step 2 (rich Model PUT) — the 7-field allowlist is a separate concern.
- Migrating sibling notebooks (`test_registered_apps.ipynb`).
- Verifying SVO query semantics on the local server beyond "non-empty when chain reaches a VP".
- Production-server smoke run.

### Step 10 — recursive nested POST (bug-089 demo)

**Markdown cell:**

- Body: explain single-call subtree POST via `/softwares` with `hasVersion → hasConfiguration → hasInput` nested inline. Auto-id at each child (omit `id`, server mints). Link-only `hasPresentation` to `EXISTING_VP`. Caps surfaced verbatim from spec: depth ≤ 8, total nodes ≤ 500, per-array length ≤ 200.

**Code cell:**
- Mint fresh root id: `RECURSIVE_ROOT_ID = f"https://w3id.org/okn/i/mint/wmobley-modflow-recursive-{uuid.uuid4().hex[:8]}"`.
- Mint fresh root label: `RECURSIVE_LABEL = "MODFLOW-2000 (recursive demo)"`.
- POST `/softwares` with payload exactly as in the orchestrator-supplied template:
  ```python
  {
    "id": RECURSIVE_ROOT_ID,
    "type": ["Software"],
    "label": [RECURSIVE_LABEL],

      "type": ["SoftwareVersion"],
      "label": ["MODFLOW-2000 v2 (recursive)"],

        "type": ["ModelConfiguration"],
        "label": ["MODFLOW-2000 default config (recursive)"],

      }]
    }]
  }
  ```

## Validation rules the notebook must follow

| Rule | Where enforced |
|------|----------------|
| Relationship arrays use object form | Audit every `hasX` literal; reject bare-string at write time. |
| `assert r.status_code in (200, 201)` for POST | All POST calls. |
| `assert r.status_code == 200` for PUT/GET | All PUT/GET calls. |
| `VERIFY_SSL = True` constant unchanged | Step 0 cell. |
| Auth header carried on every call | Existing pattern. Each `requests.*` call passes `headers=headers`. |
| Per-run uuid-suffix ids for created resources | Existing pattern. New ids in Steps 10–12 follow same shape. |
| One markdown + one code cell per step, no folding | NotebookEdit insert mode, alternating cell_type. |
| No retry-with-bare-string fallback | Code path missing entirely; v2.1.0 rejects on purpose. |

## Error handling

- POST/PUT failures → `assert` raises `AssertionError`, halts notebook. Acceptable: this is a demo notebook, fail-loud beats silent corruption.
- VP bootstrap failure (POST returns non-2xx) → assert raises with full body printed for debugging.
- Step 11 detach assertion failure (`hasVersion` not empty after PUT `hasVersion: []`) → assert with response body printed.
- Step 12 link-only label clobber detection → `assert label_after == label_before, f"bug-087 regression: label changed from {label_before} to {label_after}"`.

## Test strategy

Notebook IS the test. No separate pytest suite. Manual run protocol:

1. Run all cells top-to-bottom with `Run All`.
2. No `AssertionError`s anywhere → pass.
3. Final cell prints all four gate lines → pass.
4. `svo_count > 0` → SVO chain works end-to-end.

## Rollout

1. Make all cell edits via `NotebookEdit` against the live `.ipynb` file.
